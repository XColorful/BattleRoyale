## 六个根本原因

**1. 渲染包重命名（你指出的那个）** — `com.mojang.blaze3d.pipeline.*`、`blaze3d.PrimitiveTopology` 和 `blaze3d.platform.CompareOp` 全部迁移到 `com.mojang.renderpearl.api.pipeline.*`；`OutputTarget` 完全消失（`RenderSetup` 不再有输出目标），`BindGroupLayouts.MATRICES_PROJECTION` 拆分为 `PROJECTION` + `DYNAMIC_TRANSFORMS`。

- [CustomRenderType.java](core/src/main/java/xiao/battleroyale/client/renderer/CustomRenderType.java) — 重新导入；原本手写的 `MATRICES_PROJECTION` 现在变成了 `PROJECTION + DYNAMIC_TRANSFORMS`，这样就能精确复现 26.2 的绑定组（26.2 中该布局包含两个 uniform）。这与 26.3 自身的 `DEBUG_FILLED_SNIPPET` 一致。
- [IrisShaders.java](core/src/main/java/xiao/battleroyale/compat/iris/IrisShaders.java) — 仅重新导入。

**2. `CommandSourceStack`** — 26.3 删除了 `(…, String textName, Component displayName, …)` 构造函数；剩下两个公开的构造函数。根据每个调用点是否传入实体来拆分，而不是添加辅助类：有实体的 27 处使用实体构造函数（保留 `@s`/`~` 语义），没有实体的 11 处使用 `Component` 构造函数。涉及 `api/event/` 下的 12 个事件类，以及 `neoforge-compat/…/event/` 下的 26 个。

**3. Block 编解码 API 被删除** — `Block.simpleCodec` 和 `codec()` 在 26.3 中已不存在（方块通过 `BuiltInRegistries.BLOCK` 序列化）。从 [EntitySpawner.java](core/src/main/java/xiao/battleroyale/block/EntitySpawner.java)、[LootSpawner.java](core/src/main/java/xiao/battleroyale/block/LootSpawner.java)、[ZoneController.java](core/src/main/java/xiao/battleroyale/block/ZoneController.java) 中移除了废弃的 `CODEC` 字段和 `@Override`。`PushReaction.NORMAL` → `PUSH_PULL`（它是 26.3 的 `BlockBehaviour.Properties` 默认值，因此行为不变）。

**4. `PoseStack.mulPose(Quaternionf)` 被移除** — 现在改为 `new Matrix4f().rotate(…)`；与旧重载构建的是同一个旋转矩阵。

**5. `ServerClockManager.getTotalTicks`** → 改为 `getInstance(clock).totalTicks()`。

**6. `Player.drop(…, boolean, boolean)`** → 第三个参数现在是 `Prediction`。这里只需判断：这些是服务器端物品栏操作，没有客户端预测，所以 `Prediction.SERVER_ONLY`。
